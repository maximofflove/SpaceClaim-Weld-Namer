# SpaceClaim Weld Namer

Небольшая скриптовая утилита для **ANSYS SpaceClaim 2021 R1 / Script API V19**, предназначенная для последовательного создания Named Selection для сварных соединений и визуального контроля уже подготовленных сварных кромок.

Текущая стабильная версия — **v0.10.0**. Она фактически проверена на реальной установке SpaceClaim 2021 R1 для режима **Edges**, включая `DesignEdgeGeneral`, повторное открытие окна, последовательное создание групп, Secondary Selection, Auto Highlight и подсветку текущей пары.

> Это скриптовая утилита SpaceClaim, не DLL Add-In и не ACT-расширение.


## Почему появилась эта утилита

Эта программа появилась не как отдельный эксперимент с Python, а из вполне конкретной инженерной задачи.

При подготовке **большой детализированной submodel с большим количеством сварных соединений** я столкнулся с тем, что вручную создавать и последовательно именовать парные Named Selection для каждого шва становится слишком долго и легко допустить ошибку. При этом те же выборки затем нужны уже в Mechanical — для создания связей, проверки модели и последующей обработки усилий в сварных соединениях.

Возможности **Python / IronPython в ANSYS и SpaceClaim** продолжают приятно удивлять. Даже в SpaceClaim 2021 R1 сравнительно небольшой скрипт позволяет убрать заметную часть рутинной работы с деревом модели, не отбирая у инженера контроль над тем, какая именно геометрия относится к конкретному сварному соединению.

Поэтому SpaceClaim Weld Namer задуман именно как **полуавтоматический** инструмент:

- инженер сам выбирает реальные кромки или грани сварного соединения;
- программа создаёт следующую Named Selection `wNa / wNb`;
- текущую пару можно сразу подсветить и визуально проверить;
- созданные Named Selection затем передаются в **ANSYS Mechanical** и могут напрямую использоваться в workflow с **MPC184 Viewer**.

То есть программа не пытается автоматически «угадывать» сварные швы. Она автоматизирует повторяющуюся часть работы — именование, ведение последовательности и визуальный контроль — оставляя инженерный выбор геометрии за пользователем.

## Назначение

Пользователь выбирает одну или несколько кромок и нажимает **Create Next**. Создаётся одна Named Selection со следующим свободным именем:

```text
w1a -> w1b -> w2a -> w2b -> ... -> w99999999b
```

Несколько выбранных объектов входят в одну группу. Существующие weld-группы не перезаписываются. Регистр не учитывается, а пропуски последовательности автоматически заполняются.

Следующее имя каждый раз заново вычисляется по Named Selection **корневой детали**. Отдельного счётчика нет.

## Работа с текущей парой

Идея v0.10 — не подсвечивать автоматически сотни уже созданных сварок на большой модели, а показывать именно ту пару, с которой инженер работает сейчас:

```text
Create w5a -> подсвечивается w5a
Create w5b -> подсвечиваются w5a + w5b
Create w6a -> подсветка переключается на w6a
```

Для общего визуального контроля остаётся **Highlight All Weld Groups**.

## Почему Secondary Selection

Эксперимент с CAD color выполнялся без исключений, но на целевой установке не дал нужной индивидуальной окраски выбранных топологических кромок. Поэтому стабильная версия не изменяет цвет CAD-геометрии.

Secondary Selection:

1. подсвечивает именно геометрию Named Selection;
2. не изменяет реальные свойства отображения CAD;
3. может быть очищен независимо;
4. является post-processing: ошибка подсветки не должна отменять успешно созданную Named Selection.

## Связанный проект: MPC184 Viewer

SpaceClaim Weld Namer особенно удобно использовать совместно с **MPC184 Viewer** для ANSYS Mechanical:

**MPC184 Viewer:** https://github.com/maximofflove/MPC184Viewer

Типовой рабочий процесс:

```text
SpaceClaim Weld Namer
-> создание сторон сварных соединений w1a / w1b / w2a / w2b / ...
-> передача / обновление модели в ANSYS Mechanical
-> MPC184 Viewer
-> создание, проверка, визуализация и обработка результатов MPC184-связей сварных соединений
```

Проекты являются независимыми, но их workflow и схема именования weld-групп хорошо дополняют друг друга.

## Требования

- ANSYS SpaceClaim **2021 R1**;
- Script API **V19**;
- встроенный **IronPython 2.7**;
- перед созданием weld-групп должна быть активна **корневая деталь / ROOT component**.

Работа в других версиях SpaceClaim данным релизом не подтверждена.

## Запуск

1. Открыть модель SpaceClaim.
2. Активировать **ROOT component**.
3. Открыть `Weld_Namer.py` в Script Editor.
4. Выбрать **Script API V19**.
5. Выполнить весь файл.
6. Выбрать `Edges` или `Faces`.
7. Выделить нужную геометрию.
8. Нажать **Create Next**.

**Check Next Name** показывает следующее свободное имя без изменения модели.

## Элементы окна

- `Faces` / `Edges`;
- **Create Next**;
- **Check Next Name**;
- **Auto highlight current pair after Create**;
- **Highlight Current Pair**;
- **Highlight All Weld Groups**;
- **Clear Highlight**;
- поле сообщений.

## Примеры нумерации

| Существующие группы | Следующая группа |
|---|---|
| нет | `w1a` |
| `w1a` | `w1b` |
| `w1a`, `w1b` | `w2a` |
| `W1A`, `w1b`, `w2a` | `w2b` |
| `w1b` | `w1a` |
| `w1a`, `w2a` | `w1b` |

В последовательности участвуют только имена вида `w<number>a` и `w<number>b`.

## Подтверждённая цепочка API

Рабочее ядро намеренно не переписывалось при переходе от v0.5 к v0.10:

```text
Selection.GetActive()
-> NamedSelection.GetGroups(root)
-> NamedSelection.Create(selection, Selection.Empty())
-> проверка ровно одной новой группы
-> NamedSelection.Rename(temporary_name, target)
```

Для целевой установки V19 установлено:

- у `Part` нет требуемого свойства `Groups`;
- `NamedSelection.GetGroups(root)` работает;
- `NamedSelection.GetGroups()` без аргумента ранее приводил к null-reference из modeless callback;
- окно создаётся в UI-потоке SpaceClaim через `BeginInvoke`;
- состояние окна хранится в `AppDomain` и защищено `Monitor`.

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
